# Code of Conduct

## Our commitment

Ame is a community project. Everyone who takes part — contributors, maintainers,
testers and users — should be able to do so without harassment, intimidation or
personal attacks. This document describes the behaviour expected in every
project space and what happens when it is not met.

## Scope

This code applies to all project spaces, including GitHub issues, pull
requests, code review, discussions, release comments and any other channel used
for project work. It also applies when someone represents the project in public.

## Expected behaviour

- Be respectful. Disagree with an idea without attacking the person behind it.
- Assume good faith and give others room to be wrong while they learn.
- Critique code, design and decisions on their technical merits.
- Accept correction gracefully, and correct others without humiliating them.
- Keep discussions focused on the project and on the problem being solved.
- Respect privacy. Do not publish anyone's private information without consent.
- Credit other people's work, including upstream projects and third-party assets.

## Unacceptable behaviour

- Harassment, threats, discrimination or derogatory comments based on who
  someone is.
- Personal attacks, insults, trolling or deliberately disruptive behaviour.
- Sexualised language or uninvited sexual attention.
- Publishing private information, including addresses, credentials or private
  correspondence, without explicit permission.
- Repeated off-topic promotion, spam or deliberate derailment of discussions.
- Retaliation against anyone who reports a concern in good faith.

## Reporting

Report conduct issues privately to the project maintainer:

- GitHub: [@AbhishekS04](https://github.com/AbhishekS04) — use the contact
  method listed on the profile.

Please do not open a public issue for a conduct report. Include what happened,
where it happened and any links or screenshots that help. Reports are handled
confidentially, and the identity of a reporter is not shared without consent.

## Enforcement

Maintainers will review reports and respond in proportion to the behaviour:

1. **Correction** — a private explanation of what was wrong and what is
   expected next.
2. **Warning** — a formal warning, with consequences for repeated behaviour.
3. **Temporary restriction** — a time-limited block from project spaces.
4. **Permanent ban** — removal from all project spaces.

Maintainers may also edit, remove or reject comments, commits, issues and pull
requests that violate this code. A maintainer involved in an incident will not
take part in handling that report.

## Good faith

This code is not a tool for silencing criticism. Technical disagreement, blunt
code review, a rejected pull request or a request for more evidence are normal
parts of the project and are not violations.
